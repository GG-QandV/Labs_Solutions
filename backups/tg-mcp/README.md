## Що таке MCP

**MCP (Model Context Protocol)** — це універсальний роз'єм між AI-асистентами та зовнішніми сервісами.

Замість того щоб кожна програма (Claude, opencode, Cursor тощо) писала свій власний код для Telegram — MCP дає єдиний стандарт: AI описує що йому треба зробити («надіслати повідомлення в чат 12345», «знайти листування за запитом»), а MCP-сервер виконує. Однаковий набір інструментів працює в будь-якому MCP-сумісному додатку.

## Як це використовується

```
Клієнт (Claude/opencode/Cursor)
       │  MCP протокол (stdio)
tg-mcp │  ← «знайди повідомлення з інвойсом»
       │  → «ось 3 результати, текст, дата, посилання»
       │
Telegram API (через Telethon)
```

Агент (бот) отримує завдання від людини — наприклад «перевір чи прийшла відповідь від клієнта в Telegram». Він викликає `SearchMessages` через MCP, tg-mcp знаходить повідомлення і повертає результат. Людина не відкриває Telegram — агент зробив це сам.

### Як бот отримує можливості через MCP

Сам Telegram-бот не має вбудованих знань про те, як працювати з Telegram API. MCP-сервер (tg-mcp) дає боту «руки»: бот каже «хочу надіслати повідомлення» → звертається до MCP → MCP виконує через Telethon. Без MCP бот умів би тільки відповідати на команди, а з MCP він може самостійно шукати, аналізувати, модерувати, надсилати файли — робити все, що людина вручну робить у Telegram.

```
Людина → бот/агент (запит)
          бот/агент → tg-mcp/MCP (виклик інструменту)
                        tg-mcp → Telegram API (запит)
                        Telegram API → tg-mcp (відповідь)
          tg-mcp → бот/агент (результат)
Людина ← бот/агент (відповідь)
```

## Три вектори використання tg-mcp

tg-mcp **не замінює** звичайний Telegram Desktop чи Web. Він додає можливості, яких у звичайного клієнта немає:

### a) Спостереження та контроль процесів

Агенти, які працюють у фоні, через MCP отримують повідомлення та інформацію з робочих процесів: нові заявки в чаті, зміна статусу, файли від клієнтів, термінові повідомлення. Вони аналізують, фільтрують, шукають, підсумовують — і передають людині тільки те, що дійсно потребує уваги.

**Приклад:** агент кожні 30 хв перевіряє чат підтримки, знаходить нові повідомлення зі словом «терміново», класифікує їх і надсилає зведення.

### b) Пряма комунікація з агентом

Людина може напряму спілкуватися з агентом через Telegram: поставити задачу («знайди в чаті 127 переписку про PDF за останній тиждень», «напиши клієнту що ми отримали його файли»), отримати відповідь або звіт, запитати статус процесів. Агент через tg-mcp виконує дії в Telegram від імені людини і повертає результат.

**Приклад:** «перешли це повідомлення в чат з менеджером» → агент викликає `ForwardMessage` → готово.

### c) Чим агент з tg-mcp відрізняється від звичайного бота

Звичайний Telegram-бот (скриптовий, не-AI) працює за жорстко прописаними сценаріями: команда → дія. Він не розуміє контекст, не аналізує, не приймає рішень.

Агент з tg-mcp — це AI, який:

- **розуміє** природну мову, а не тільки команди
- **приймає рішення** — що важливо, що ні, кому відповісти
- **адаптується** — не потребує переписування коду під новий сценарій
- **комбінує дії** — може знайти повідомлення, проаналізувати його, надіслати звіт в інший чат — все одним запитом від людини
- **пам'ятає контекст** — розуміє про що мова, навіть якщо запит сформульовано неідеально

**Коротко:** бот робить тільки те, що йому запрограмували. Агент з MCP розуміє що треба зробити і знає як.

## Вигода

- **Єдиний інтерфейс** — AI знає тільки MCP, не знає як влаштований Telegram API
- **Замінює людину в рутині** — агент може стежити за чатами, відповідати, шукати, модерувати без участі людини
- **Працює в будь-якому MCP-додатку** — Claude Desktop, opencode, Cursor, власні скрипти — один сервер для всього
- **Безпека** — API ключі живуть тільки в середині сервера, AI їх не бачить
- **Готовий до навантаження** — Rate Limiter не дає заблокувати акаунт FloodWait-ами

## Як це працює всередині

- **MCP Server** — реєструє всі інструменти автоматично, виконує виклики від AI-агента
- **Telegram Client** — підключається до Telegram через ваш API ключ (env `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`)
- **Rate Limiter** — не дає перевантажити Telegram: ліміти на чат, глобальні, денний ліміт на пошук, пріоритети (термінові операції виконуються першими)
- **FloodWait** — якщо Telegram просить почекати, сервер чекає і повторює (до 3 разів)
- **QR Auth** — авторизація через QR-код (у терміналі + PNG-файл)

# ПАТЧ v1.1 к «анализ_логик_промпт.md» — двойной таргет установки

Применяется поверх исходного промпта STT-MVP (whisper.cpp + PipeWire + SQLite + облачный перевод).
Цель: сервис **системно устанавливается на два таргета** — ноутбук Linux Mint Cinnamon и VPS Netcup 1000 G12 (headless, парк демо с Traefik + OpsHub). Ядро (STT-пайплайн, SQLite, jobs, BYOK, watchdog-логика) — общее; различаются захват звука, упаковка, сеть и жизненный цикл.

---

## 1. Профили запуска (заменяет допущение «только десктоп»)

Env `APP_PROFILE=desktop|server`, задаётся инсталлятором, влияет только на слой ввода и упаковку:

| Аспект         | `desktop` (Mint Cinnamon)                                                                    | `server` (VPS 1000 G12)                                                                                                                                 |
| -------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Источник аудио | PipeWire live-захват (звук встречи + микрофон раздельно, wpctl/pw-dump discovery)            | **PipeWire отсутствует.** Два входа: (а) загрузка аудиофайлов wav/mp3/ogg/m4a; (б) микрофон браузера через getUserMedia → WebSocket-стрим PCM на сервер |
| UI-адрес       | http://127.0.0.1:8790 (localhost — getUserMedia разрешён без TLS)                            | https://stt.solutions.dpdns.org за Traefik (**getUserMedia требует HTTPS** — без TLS браузер не даст микрофон)                                          |
| Доступ         | Без авторизации (личная машина)                                                              | Временный токен-сессия TTL 1 ч (как в остальных демо парка) + rate-limit                                                                                |
| Упаковка       | **Нативно, без Docker**: install.sh + systemd **user** unit                                  | **Docker-контейнер** по конвенциям парка (см. §3)                                                                                                       |
| Лимиты RAM     | systemd: MemoryHigh=1600M, MemoryMax=1850M; watchdog читает cgroup v2 `memory.current` юнита | compose: `mem_limit: 2048m`, `restart: on-failure` (нативный OOM-рестарт); watchdog читает `/sys/fs/cgroup/memory.current` контейнера                   |
| Retention      | Управляет пользователь (настройка в UI, дефолт — хранить)                                    | Ежесуточная очистка 03:00 анонимных сессий + предупреждение за 15 мин с одноразовым «Postpone 1 hour»; дисклеймер «demo only, test data»                |
| OpsHub         | Не используется (OPSHUB_* пустые → drop-in клиент выключен)                                  | Обязателен: heartbeat, логи ERROR/CRITICAL, label `demo=true`, автостоп 30 мин, ночной рестарт 04:00                                                    |

Правило кода: модуль захвата — за интерфейсом `AudioSource` (реализации `PipeWireSource`, `FileSource`, `BrowserStreamSource`); ядро пайплайна (VAD → whisper.cpp → SQLite → translate-jobs) не знает, из какого профиля пришёл PCM 16 kHz mono.

## 2. Установка на Mint Cinnamon (десктоп-таргет)

`install.sh` (идемпотентный, с откатом при ошибке):

1. Проверки: x86_64, AVX2 (`grep avx2 /proc/cpuinfo`; без AVX2 — сборка whisper.cpp в generic-режиме с предупреждением о скорости), свободная RAM ≥ 4 GB, диск ≥ 2 GB.
2. Зависимости apt: `pipewire wireplumber libpipewire-0.3-dev build-essential cmake python3 ffmpeg` (Mint 21/22 — Ubuntu-база; если активен PulseAudio — в README инструкция миграции на PipeWire, без автоматической замены).
3. Сборка whisper.cpp → `~/.local/share/stt-mvp/bin/`; загрузка `ggml-base.bin` с проверкой sha256.
4. Python-часть — **uv** в `~/.local/share/stt-mvp/` (без загрязнения системного питона).
5. systemd user unit `~/.config/systemd/user/stt-mvp.service`: `MemoryHigh=1600M`, `MemoryMax=1850M`, `EnvironmentFile=%h/.config/stt-mvp/env` (chmod 0600, BYOK-ключ при желании), `Restart=on-failure`; затем `systemctl --user enable --now` + `loginctl enable-linger $USER` (сервис живёт без открытой сессии — это и есть «системная установка» в границах user-space Mint).
6. Ярлык `.desktop` для меню Cinnamon (открывает http://127.0.0.1:8790).
7. `uninstall.sh`: стоп юнита, удаление файлов, опционально — данных.

## 3. Установка на VPS (server-таргет)

Docker-образ (multi-stage: сборка whisper.cpp + uv sync → slim-рантайм, модель в кэш-слое), compose по конвенциям парка:

```yaml
services:
  stt-demo:
    build: .
    container_name: stt-demo
    restart: on-failure
    mem_limit: 2048m
    cpus: 2.0
    environment:
      - APP_PROFILE=server
      - PUBLIC_BASE_URL=https://stt.solutions.dpdns.org
      - OPSHUB_URL=http://opshub:8700
      - OPSHUB_KEY=${OPSHUB_KEY}
      - OPSHUB_SERVICE=stt-demo
      - TRANSLATE_API_KEY=${TRANSLATE_API_KEY}   # ограниченный ключ демо; BYOK-сессии поверх
    volumes: [ /srv/demos/stt-demo/data:/data ]
    networks: [ web, opsnet ]
    labels:
      - "demo=true"
      - "traefik.enable=true"
      - "traefik.http.routers.stt.rule=Host(`stt.solutions.dpdns.org`)"
      - "traefik.http.routers.stt.entrypoints=websecure"
      - "traefik.http.routers.stt.tls.certresolver=le"
      - "traefik.http.services.stt.loadbalancer.server.port=8790"
```

Ограничения server-профиля (бюджет 2 GB и правило «до 3 демо в RAM»): один экземпляр whisper.cpp base; одна активная STT-задача, остальные в очереди с позицией; файл ≤ 25 MB / ≤ 20 минут аудио; браузер-стрим — одна параллельная сессия на токен. Холодный старт (запуск из OpsHub): модель whisper грузится лениво при первой задаче, UI показывает «warming up».

## 4. Изменения BYOK (дополнение, не замена)

- Desktop: как в исходном промпте (RAM-only, TTL 60 мин, Revoke, LogRedactor) + EnvironmentFile 0600 для постоянного личного ключа.
- Server: BYOK принимать **только** по HTTPS POST (TLS гарантирует Traefik); ключ владельца демо — из `.env` парка; запрет попадания ключей в docker logs (LogRedactor применяется и к stdout, который собирает Docker); в OpsHub ошибки уходят уже после редакции ключей.

## 5. Изменения критериев приёмки

Заменить критерий 1 и добавить 13–16:

1. *(было: «запускается на Linux Mint Cinnamon без Docker…»)* → «Профиль `desktop` устанавливается на Linux Mint Cinnamon нативно (install.sh, systemd user unit, без Docker/GPU); профиль `server` разворачивается на VPS одним контейнером по конвенциям парка (Traefik + OpsHub)».
2. Server: загруженный аудиофайл и микрофон браузера (по HTTPS) проходят тот же пайплайн STT→перевод, что и live-захват на десктопе.
3. Server: очистка 03:00 с предупреждением и отсрочкой; сессии изолированы токенами.
4. Server: сервис виден в OpsHub (heartbeat, ошибки, start/stop, автостоп, ночной рестарт), корректно переживает холодный старт.
5. Один репозиторий, одно ядро: `APP_PROFILE` — единственная развилка; модульные тесты ядра проходят без PipeWire и без Docker.

## 6. Что НЕ меняется

Весь STT-пайплайн (VAD, whisper.cpp base, сегменты, SQLite WAL + single writer, jobs recovery, backoff ≤3 попыток), режимы live_literal/post_clean с правилами редактора, экспорт TXT/SRT/VTT/JSON, деградация без потери данных, таблица RAM-бюджетов ядра, health/ready, graceful shutdown — остаются как в исходном промпте и обязаны работать в обоих профилях.

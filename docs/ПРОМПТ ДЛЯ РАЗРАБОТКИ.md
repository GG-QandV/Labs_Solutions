Вот полноценный технический промпт для создания демо-шаблона на Cloudflare.

***

## ПРОМПТ ДЛЯ РАЗРАБОТКИ

Ты — senior full-stack разработчик. Создай демонстрационный сервис генерации PDF-отчётов на инфраструктуре Cloudflare (Workers + Pages). Это не production-система для конкретного заказчика, а универсальный переиспользуемый demo-шаблон, который в дальнейшем масштабируется под разные источники данных и клиентов.

### Цель проекта

Показать потенциальному заказчику живое демо: он вставляет ссылку на свой Google Sheet (публичный "по ссылке" или созданный на тестовом Google-аккаунте), система валидирует объём данных, строит структуру автоматически, генерирует брендированный PDF-отчёт с изображениями и отправляет готовый файл на email по кнопке.

### Общая архитектура

```
[Страница] → вставка ссылки на Google Sheet
     ↓
[Валидатор] → проверка объёма/формата/доступности
     ↓
[Sheet-коннектор] → чтение данных, парсинг в универсальную структуру
     ↓
[PDF Engine] → HTML/CSS-шаблон + Browser Rendering
     ↓
[PDF] → отправка на email пользователя
```

Ключевое архитектурное правило: **PDF Engine принимает только нормализованный внутренний формат данных (назови его `ReportData`), а не сырые данные Google Sheets напрямую**. Sheet-коннектор — единственный модуль, который знает про Google API. Это даёт возможность в будущем заменить Google Sheets на любой другой источник (форма, CRM, дашборд) без переписывания PDF Engine.

### Технологический стек

- **Frontend**: Cloudflare Pages, простой React (Vite) или чистый HTML/CSS/JS — без лишних зависимостей.
- **Backend**: Cloudflare Workers, TypeScript.
- **PDF-рендеринг**: Cloudflare Browser Rendering API (`@cloudflare/puppeteer`), генерация PDF через `page.pdf()` из HTML/CSS-шаблона.
- **Доступ к Google Sheets**: только через **публичный экспорт таблицы** без OAuth и без сервисных аккаунтов — самый простой и безопасный вариант для демо: `https://docs.google.com/spreadsheets/d/{id}/gviz/tq?tqx=out:csv` (или аналогичный публичный CSV-экспорт по расшаренной "по ссылке" таблице). Никаких кредов, токенов Google, сервисных аккаунтов на этом этапе.
- **Хранение временного состояния задачи** (статус генерации, токен доступа, время истечения): Cloudflare KV с TTL.
- **Email**: Cloudflare Email Workers API или Resend — отправка письма с вложением PDF, шаблон письма должен быть заменяемой константой/конфигом (не хардкод текста внутри логики отправки).
- **Хранение файлов**: не нужно постоянное хранение — PDF генерируется по запросу и либо сразу отдаётся, либо временно кладётся в R2 с автоудалением через TTL/lifecycle rule, если нужно прикладывать к письму.

### Модуль 1: Ввод и получение доступа

- Простая страница с полем "Вставьте ссылку на ваш Google Sheet" и кнопкой "Проверить доступ".
- Опционально: генерация одноразовой ссылки/токена с ограничением по времени (например, 1 час или до конца рабочего дня) — это НЕ полноценный OAuth, а простой временный токен доступа к самому демо-сервису (защита от постороннего использования, а не авторизация в Google). Храни токен и его TTL в Cloudflare KV.
- По истечении токена — доступ к функции генерации блокируется с понятным сообщением.

### Модуль 2: Валидация Google Sheet

Перед генерацией PDF выполнить проверку и вернуть **детальный отчёт об ошибках**, а не общий "не получилось":

- Доступность: таблица открывается по публичной ссылке (не приватная, доступ не запрещён).
- Формат: данные корректно парсятся как CSV/табличная структура.
- Объём: количество строк/объём данных не превышает расчётный лимит на 10 страниц A4/Legal (рассчитай примерный лимит строк на основе плотности шаблона, например ~40-60 строк данных на 10 страниц — точное число зависит от макета, заложи это как настраиваемый параметр).
- Соотношение видимых/скрытых данных: если в таблице есть скрытые строки/столбцы, отчёт должен показать это отдельно (сколько скрыто, сколько будет реально использовано).
- Результат валидации — структурированный список: `{ ok: boolean, errors: [{ code, message, details }] }`, показываемый пользователю построчно на странице, а не одной фразой.

### Модуль 3: Автоматическое построение структуры

- Система **не знает заранее** структуру таблицы — она должна сама определить: заголовки столбцов (первая строка), типы данных в столбцах (текст, число, URL/ссылка на изображение, дата), и на основе этого динамически сформировать `ReportData`.
- Определение "это ссылка на изображение": проверка по регулярке на расширение (`.png`, `.jpg`, `.jpeg`, `.webp`) в значении ячейки или по формату Google Drive URL.
- Каждая строка таблицы → один блок/карточка в PDF. Каждый столбец → поле в этой карточке. Изображения из ячеек вставляются в блок карточки.

### Модуль 4: Обработка изображений

- Ссылка на изображение берётся прямо из содержимого ячейки (не через Drive API, не через креды — просто публичный URL или прямая ссылка на файл, доступный по ссылке "любой пользователь с ссылкой").
- Изображение масштабируется с сохранением пропорций так, чтобы поместиться в границы стандартного блока страницы: подбирается коэффициент масштабирования по большей из двух осей (ширина или высота), при котором изображение целиком укладывается в контейнер без обрезки и без деформации (`object-fit: contain`, аналог `.thumbnail()` в Pillow — уменьшение до посадки в bounding box).
- Если изображение недоступно/битая ссылка — не рушить весь рендер, а показать в этом блоке плейсхолдер "изображение недоступно" и зафиксировать это в отчёте валидации.

### Модуль 5: PDF-шаблон

Требования к дизайну:

- Минималистичный, чистый, композиционно аккуратный дизайн — цель показать "это шаблон, сюда можно вставить что угодно", а не готовое решение под конкретную нишу.
- Настраиваемые зоны для брендинга: логотип (placeholder-изображение с подсказкой "ваш логотип"), название компании (placeholder-текст), акцентный цвет (CSS-переменная, легко заменяемая).
- Структура: обложка (логотип, название компании, дата, номер отчёта) + повторяемые карточки данных (одна карточка на строку таблицы) + при необходимости — разбивка на страницы при превышении лимита.
- CSS: `@page` для A4, `break-inside: avoid` для карточек, аккуратная типографика, минимум цветов (1 акцентный + нейтральные серые), достаточные отступы (whitespace), без визуального "шума".
- Один шаблон на старте, но структура кода/шаблонов должна позволять просто добавить `template-2.html`, `template-3.html` без изменения PDF Engine (шаблон передаётся как параметр в конфиг рендера).

### Модуль 6: Генерация и отправка

- Кнопка "Сгенерировать PDF и отправить на почту".
- Пользователь вводит email, куда отправить результат.
- PDF Engine рендерит HTML-шаблон с подставленными данными в Browser Rendering, получает PDF-buffer.
- Email отправляется через настраиваемый шаблон письма (тема и текст — конфигурируемые константы, минимум: "Здравствуйте! Ваш PDF-отчёт готов, файл во вложении.") с PDF как вложением.
- Пользователю на странице — статус: "Генерация...", "Отправлено на {email}", либо детальная ошибка, если что-то не удалось на любом из этапов (валидация / рендер / отправка).

### Структура проекта

```
/apps
  /web                     — Cloudflare Pages: страница ввода, статус, отчёт валидации
  /worker                  — Cloudflare Worker: API
/packages
  /report-schema           — TypeScript-типы ReportData, ReportBlock, ValidationResult
  /sheet-connector         — модуль: CSV-ссылка → ReportData (единственное место, знающее про Google Sheets)
  /report-renderer         — HTML/CSS-шаблоны (template-1 и далее), логика подстановки данных
  /pdf-engine               — вызов Browser Rendering, генерация PDF-buffer
  /email-sender             — отправка письма с вложением, конфигурируемый шаблон письма
  /access-token             — временный токен доступа к демо (KV + TTL)
```

### Явное разделение "сейчас" и "потом"

Не реализовывать в этой версии: OAuth Google, сервисные аккаунты, постоянное хранение файлов/истории, авторизацию пользователей, несколько ролей, мультитенантность, редактор шаблонов в UI. Все эти пункты — зона роста, но код должен быть организован так, чтобы `sheet-connector` можно было заменить другим коннектором (форма, CRM, дашборд) без изменения `pdf-engine` и `report-renderer`.

### Итоговый критерий готовности демо

1. Пользователь вставляет ссылку на публичный Google Sheet.
2. Получает временный токен доступа (таймер).
3. Видит детальный отчёт валидации (объём, скрытые данные, формат, проблемные изображения).
4. Если всё ок — нажимает "Сгенерировать PDF".
5. Система сама строит структуру карточек из таблицы, вставляет и масштабирует изображения.
6. PDF рендерится в минималистичном настраиваемом брендированном шаблоне (логотип/название — placeholder).
7. Файл отправляется на указанный email с простым конфигурируемым письмом.

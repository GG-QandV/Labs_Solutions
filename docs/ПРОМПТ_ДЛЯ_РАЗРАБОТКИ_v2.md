# ПРОМПТ ДЛЯ РАЗРАБОТКИ (v2, оптимизированный)

Ты — senior full-stack разработчик. Создай демонстрационный сервис генерации PDF-отчётов на инфраструктуре Cloudflare (Workers + Pages) и задеплой его на домен **solutions.dpdns.org**. Это универсальный переиспользуемый demo-шаблон, который в дальнейшем масштабируется под разные источники данных и клиентов.

## Жёсткие ограничения окружения (соблюдать без исключений)

- Аккаунт Cloudflare: **только Workers Free plan**. Всё решение обязано работать в лимитах Free:
  - Workers: 100 000 запросов/день, 10 ms CPU на запрос (тяжёлая работа — только через привязки Browser Rendering / R2 / KV, не в CPU Worker'а).
  - Browser Rendering: **10 минут браузерного времени в день, 3 конкурентных браузера**. Это бюджет демо — каждая генерация PDF должна укладываться в ~10–20 секунд браузерного времени; закрывать браузер сразу после `page.pdf()`.
  - **Fallback при исчерпании лимита Browser Rendering (ошибка 429)**: автоматически переключаться на генерацию PDF через `pdf-lib` (чистый JS, без браузера) — упрощённый рендер того же `ReportData` (без CSS-шаблона, но с той же структурой карточек и изображениями). Пользователю показывать пометку "simplified rendering mode".
  - Cloudflare Queues на Free недоступны — см. раздел «Генерация».
- Email: **Resend** (free tier: 100 писем/день, 1 верифицированный домен). Cloudflare Email Routing на Free не умеет отправлять письма с вложениями на произвольные внешние адреса, поэтому Resend — обязательная замена. Отправка с адреса вида `reports@solutions.dpdns.org`; в деплой-инструкции описать верификацию домена в Resend через DNS-записи (SPF, DKIM) в Cloudflare DNS.
- Хранилища: Cloudflare KV (состояние задач, токены, rate-limit) и R2 (временные файлы: загруженные изображения и, при необходимости, готовые PDF) — оба в пределах Free-квот, с TTL/lifecycle-автоудалением (24 часа).

## Цель проекта

Показать потенциальному заказчику живое демо: он вставляет ссылку на свой публичный Google Sheet, система валидирует данные, строит структуру автоматически, генерирует брендированный PDF-отчёт с изображениями и отправляет файл на email.

## Общая архитектура

```
[Страница] → ссылка на Google Sheet (+ опциональная загрузка изображений с устройства)
     ↓
[Валидатор] → доступность / формат / объём / изображения
     ↓
[Sheet-коннектор] → чтение CSV, парсинг в ReportData
     ↓
[PDF Engine] → HTML/CSS-шаблон + Browser Rendering (fallback: pdf-lib)
     ↓
[PDF] → отправка на email через Resend
```

Ключевое архитектурное правило: **PDF Engine принимает только нормализованный внутренний формат `ReportData`**, а не сырые данные Google Sheets. `sheet-connector` — единственный модуль, знающий про Google. Это позволяет позже заменить источник (форма, CRM, дашборд) без переписывания PDF Engine.

## Технологический стек

- **Frontend**: Cloudflare Pages, React + Vite, минимум зависимостей.
- **Backend**: Cloudflare Workers, TypeScript.
- **PDF**: `@cloudflare/puppeteer` (Browser Rendering) + fallback `pdf-lib`.
- **Google Sheets**: только публичный CSV-экспорт `https://docs.google.com/spreadsheets/d/{id}/gviz/tq?tqx=out:csv` (и/или `export?format=csv`). Никакого OAuth, сервисных аккаунтов, кредов.
- **Монорепо**: **pnpm workspaces + Turborepo** — быстрая сборка с кэшированием, лёгкое добавление новых apps/packages при росте числа страниц/сервисов.
- **Email**: Resend SDK, шаблон письма — конфигурируемая константа (не хардкод внутри логики отправки).
- **i18n**: весь текст UI и писем — только через словари строк (`/locales/en.json`). Стартовый язык — **английский**; структура должна позволять добавить `ru.json` и др. без правки компонентов. В UI — заглушка переключателя языка (активен только EN).

## Модуль 1: Ввод и доступ

- Страница с полем "Paste your Google Sheet link" и кнопкой "Check access".
- Генерация временного токена доступа к демо (TTL 1 час, хранится в KV). Не OAuth — просто защита демо от постороннего использования. На странице — таймер оставшегося времени.
- По истечении токена генерация блокируется с понятным сообщением и кнопкой запросить новый токен.

## Модуль 2: Валидация Google Sheet

Возвращать **детальный построчный отчёт**, формат `{ ok: boolean, errors: [{ code, message, details }], warnings: [...] }`:

- Доступность: таблица открывается по публичной ссылке.
- Формат: данные парсятся как CSV.
- Объём: лимит строк из расчёта 10 страниц A4/Legal (~40–60 строк, настраиваемый параметр конфига).
- Скрытые строки/столбцы — **best effort**: сравнить выгрузки `gviz` и `export?format=csv`; при расхождении показать warning "N rows may be hidden in the source sheet". Гарантированной детекции скрытых данных через публичный CSV нет — это ограничение фиксируется в отчёте как warning, а не error.
- Проверка изображений: для каждой image-ячейки — HEAD/GET-проверка доступности URL; недоступные — в отчёт (warning, не блокирует генерацию).

## Модуль 3: Автоматическое построение структуры

- Система заранее не знает структуру: определяет заголовки (первая строка), типы столбцов (текст, число, дата, URL, image-URL) и формирует `ReportData` динамически.
- Детекция image-URL: регулярка на расширения `.png|.jpg|.jpeg|.webp` или формат Google Drive URL.
- Каждая строка → карточка в PDF, каждый столбец → поле карточки.

## Модуль 4: Изображения (два потока, A+B)

**Поток A — URL в ячейках:**
- Публичный URL из ячейки используется напрямую.
- **Google Drive ссылки**: авто-конвертация `drive.google.com/file/d/{id}/...` и `open?id={id}` → `https://drive.google.com/thumbnail?id={id}&sz=w2000` (безопасный вариант без кредов; работает только для файлов, расшаренных "anyone with the link"). Если thumbnail-запрос вернул не-изображение/ошибку → плейсхолдер + запись в отчёт валидации.
- Все внешние изображения при рендере проксировать через Worker-endpoint (`/api/img-proxy?url=...`) с whitelist-валидацией URL (только http/https, запрет внутренних адресов — защита от SSRF (Server-Side Request Forgery — подделка запросов со стороны сервера)) и лимитом размера файла (например, 5 MB).

**Поток B — загрузка с устройства:**
- На странице после валидации таблицы: список строк с image-полями; для строк с битой/отсутствующей ссылкой — кнопка "Upload image" (drag-and-drop / выбор файла, ПК и мобильные).
- Файл грузится через Worker в **R2** с ключом `{jobId}/{rowIndex}.{ext}`, TTL/lifecycle 24 ч, лимит 5 MB, допустимые типы: png/jpg/jpeg/webp.
- Приоритет: загруженный файл (B) перекрывает URL из ячейки (A).

**Масштабирование**: изображение вписывается в контейнер карточки без обрезки и деформации — `object-fit: contain` (аналог `.thumbnail()` в Pillow). Битые изображения → плейсхолдер "image unavailable", рендер не падает.

## Модуль 5: PDF-шаблон

- Минималистичный, чистый дизайн — "это шаблон, сюда можно вставить что угодно".
- Брендинг-зоны: логотип (placeholder "your logo"), название компании (placeholder), акцентный цвет — CSS-переменная.
- Структура: обложка (логотип, компания, дата, номер отчёта) + повторяемые карточки + автоматическая разбивка на страницы.
- CSS: `@page` с **переключаемым форматом A4 / Legal** (кнопка-переключатель в UI, параметр в конфиге рендера), `break-inside: avoid` для карточек, 1 акцентный цвет + нейтральные серые, достаточный whitespace.
- Шаблон передаётся параметром в конфиг рендера; добавление `template-2.html` не должно требовать изменений PDF Engine.

## Модуль 6: Генерация и отправка

- Кнопка "Generate PDF & send to email", поле ввода email.
- **Архитектура генерации — асинхронно-готовая, исполняется синхронно** (Queues на Free недоступны):
  - Endpoint `POST /api/jobs` создаёт job в KV (`status: pending`) и запускает обработку через `ctx.waitUntil()` (обработка после ответа, до 30 с wall-time).
  - Frontend опрашивает `GET /api/jobs/{id}` (polling каждые 2 с): `pending → validating → rendering → sending → done | error{stage, message}`.
  - Логика обработчика job изолирована в отдельной функции `processJob(job)` — при апгрейде плана она подключается consumer'ом Cloudflare Queues **без изменения остального кода** (зафиксировать это комментарием и TODO в коде).
- Email через Resend: конфигурируемые тема/текст ("Hello! Your PDF report is ready, see attachment."), PDF вложением. Если PDF > лимита вложения — класть в R2 и слать ссылку с TTL 24 ч.
- Статусы на странице построчно: "Generating…", "Sent to {email}", либо детальная ошибка с указанием этапа (validation / render / email).

## Защита от абьюза

- Rate-limit в KV: максимум **5 генераций/час на токен** и **10/час на IP** (значения — конфиг). Превышение → 429 с человекочитаемым сообщением и временем сброса.
- Валидация email (синтаксис + запрет disposable-доменов по короткому списку — конфиг).
- Лимит суточных отправок согласован с квотой Resend (100/день): глобальный счётчик в KV, при исчерпании — статус "daily email quota reached, try tomorrow".
- Все лимиты — в одном конфиг-файле, чтобы при масштабировании поднять значения или заменить KV-rate-limit на Cloudflare Rate Limiting rules без правки бизнес-логики.

```
  /pdf-engine     — Browser Rendering + fallback pdf-lib, выбор шаблона и формата (A4/Legal)
  /email-sender   — Resend, конфигурируемый шаблон письма
  /access-token   — временный токен демо (KV + TTL)
  /rate-limit     — счётчики KV (токен / IP / суточная email-квота)
  /i18n           — словари строк (en.json, каркас для добавления языков)
turbo.json, pnpm-workspace.yaml
```

## Деплой (обязательная часть результата)

Готовый пустой домен на Cloudflare: **solutions.dpdns.org**. Предоставить пошаговую инструкцию + команды:

1. `wrangler` конфиги для Worker (bindings: Browser Rendering, KV namespaces, R2 bucket, секрет `RESEND_API_KEY`).
2. Создание KV namespaces и R2 bucket (+ lifecycle rule на 24 ч).
3. Деплой Pages, привязка custom domain `solutions.dpdns.org`; Worker — на `solutions.dpdns.org/api/*` (route) либо отдельный поддомен `api.solutions.dpdns.org` — выбрать и обосновать один вариант.
4. Верификация `solutions.dpdns.org` в Resend (DNS-записи SPF/DKIM в Cloudflare).
5. Smoke-чеклист после деплоя: тестовый Sheet → валидация → генерация → письмо получено.

OAuth Google, сервисные аккаунты, постоянное хранение файлов/истории, авторизация пользователей, роли, мультитенантность, редактор шаблонов в UI, Cloudflare Queues (код готов к подключению). `sheet-connector` заменяем другим коннектором без изменения `pdf-engine` и `report-renderer`.

## Критерий готовности демо

1. Пользователь вставляет ссылку на публичный Google Sheet.
2. Получает временный токен (таймер на странице).
3. Видит детальный отчёт валидации (объём, warnings по скрытым данным, формат, проблемные изображения).
4. Может догрузить изображения с устройства для проблемных строк (поток B).
5. Выбирает формат страницы (A4/Legal), нажимает "Generate PDF".
6. Система строит карточки, вставляет и масштабирует изображения; при исчерпании лимита Browser Rendering — fallback pdf-lib с пометкой.
7. PDF в минималистичном брендируемом шаблоне уходит на указанный email через Resend.
8. Всё задеплоено и работает на `solutions.dpdns.org`; лимиты Free-плана и rate-limit соблюдены.
